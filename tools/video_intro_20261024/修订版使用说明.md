# 修订版制作与核验

也就是说，最终确认版以EID、GoodTrip、控制台和跳舞为重点，其他模组与新人物简略带过，187秒、38条字幕，保留可编辑OpenFilm工程与全部旧稿。

## 当前文件

- `revision_storyboard.json`：用户最后确认的文案与镜头表，11段、31个实际画面片段；没有章节报幕和文字说明页。
- `build_revision.py`：复制并校验实际使用的录像/截图，生成全画面时间线、字幕与音频安排；更改已有文件前另存逐字旧版。
- `revision_studio.py`：通过OpenFilm原生API设置字幕、提交异步预览/正式导出、取得状态。
- `verify_revision.py`：核验最终187秒/1080p60/11220帧/38字幕，完整解码、响度、素材与工程指纹及旧成片保留。
- `revision_capture.py`：配对ELF与当前PID校验后进行取图、输入与原局状态核查，禁止detach和覆盖旧证据；长命令必须留意复用客户端的默认15秒超时与192字节控制台长度。
- `草稿归档/五分二十七秒未采用文案.json`：用户否定的长稿逐字保留，不能当作本轮交付脚本。

文档记录在`docs/项目介绍视频修订方案与记录-20261024.md`，其中最初五分钟方案只作历史，以后续用户审稿的最终方案为准。

## 镜头与声音

EID27秒、GoodTrip22秒、控制台25秒、跳舞18秒。GoodTrip和跳舞来自本轮Switch原生30秒录像，不依赖离线的OBS采集卡。原生录像约1280×720/30fps，按60fps输出时重复源帧，不宣称采集到了60个不同实机帧。用户10月20日的1920×1080/60fps录像继续用于EID、控制台等内容。

GoodTrip源片按原生地图键拍摄，临时关闭其自定义LSTICK绑定以避开Repentance Plus的同键菜单，其他模组保持加载；拍完恢复OverlayKeyController=10、原房入口97、位置560/560与暂停。最终采用单次从原房间选择商店的清晰演示，不将选房未成功的片段说成成功返回。

全部画面正常速度，完整保留16:9；没有边栏、品牌框、编号、进度条或黑底章节页。实机截图保留简短来源标记。舞蹈段使用原生游戏音轨，停放底乐；其他段使用低音量原创器乐。Movies原录像中的麦克风声音全部排除，没有合成旁白或冒充哈基米。

原生字幕由无声WAV时钟同名VTT承载，以免分段音乐造成字幕缺失；这份VTT是人工撰写的介绍文字，不是语音转写。最后导出必须启用burnSubtitles，普通CLI render不烧录Studio的字幕。

## 命令与结果位置

在主仓库运行，已有工程路径`/Users/kelinls/Movies/项目介绍-OpenFilm-20261024`：

```sh
python3 tools/video_intro_20261024/build_revision.py
python3 tools/video_intro_20261024/revision_studio.py style
python3 tools/video_intro_20261024/revision_studio.py preview
```

检查逐段静帧与短样片后，正式导出：

```sh
python3 tools/video_intro_20261024/revision_studio.py render
python3 tools/video_intro_20261024/revision_studio.py status
```

render提交队列即返回，状态应按需要查询，不循环忙等。完成后后台运行：

```sh
python3 tools/video_intro_20261024/verify_revision.py
```

导出文件名为`以撒Switch模组项目-介绍视频-最终修订版.mp4`及同名SRT；核验保存在`核验-确认版/`。187秒正式输出总帧数11220，不能引用初版120秒/7200帧或长稿327秒/19620帧作为本版结果。

旧成片和初版Git快照保留；旧HTML、文案、字幕、原生样式与被覆盖草稿另存Movies的`版本备份/`。用户后续手动编辑工程时，先读最新film.html与页面，不直接重跑生成脚本覆盖编辑。
